================================================================================
CODE_ALL EXPERIMENT COMPARISON — THESIS DOCUMENTATION
================================================================================
Date: 2026-03-23
Purpose: Document how each experiment folder differs for thesis writing and
         identify what to change in new code for better results.

All experiments share:
  - Asset: QQQ (NASDAQ-100 constituents)
  - Frequency: Daily
  - RL Algorithm: Soft Actor-Critic (SAC)
  - Architecture: Per-asset temporal encoder → Cross-sectional multi-head
    attention (with global token) → Dirichlet policy → Twin critics
  - Walk-Forward Optimization (WFO): Sliding (non-anchored) window
    - Train: 60 months (5 years)
    - Validation: 12 months (1 year)
    - Test: 12 months (1 year)
    - Step: 12 months (1 year)
    - Embargo: 0 days
  - Training: 50 epochs, min_epochs=20, patience=8, gradient_steps=2
  - Transaction cost: 2 bps
  - Turnover penalty: 0.003
  - Annualization: 252 (daily)
  - Alpha: Fixed at 0.2 (auto_alpha=False) — fixed because Dirichlet entropy
    caused alpha divergence when auto-tuned
  - Lookback window: 60 trading days (~3 months)
  - Weight smoothing beta: 0.3 (EMA: executed_w = 0.3*target + 0.7*previous)
  - Buffer capacity: 20,000
  - Warmup steps: 500 (random Dirichlet actions)
  - Critic LR: 5e-4
  - Gamma: 0.99
  - Embed dim: 64
  - Attention heads: 4
  - Scorer hidden: 128
  - Critic hidden: 256


================================================================================
1) QQQ_LSTM_DAILY_1 — Flat Dirichlet with Log-Return Reward
================================================================================

1. GENERAL RL APPROACH:
   SAC with FLAT Dirichlet-(N+1) policy (hierarchical=False).
   The agent outputs a Dirichlet distribution over N stocks + 1 cash position.
   All weights are positive and sum to 1. Cash is part of the simplex.

2. NUMBER OF CONFIGS: 3

3. CONFIGS:
   A) "small_k20"
      - LSTM: hidden=64, layers=1, dropout=0.0
      - top_k=20 (momentum-filtered top 20 stocks)
      - lr_actor=3e-4, batch_size=128
      - (~57s/epoch)

   B) "small_k30"
      - LSTM: hidden=64, layers=1, dropout=0.0
      - top_k=30 (momentum-filtered top 30 stocks)
      - lr_actor=3e-4, batch_size=128
      - (~69s/epoch)

   C) "medium_k20"
      - LSTM: hidden=128, layers=1, dropout=0.1
      - top_k=20
      - lr_actor=3e-4, batch_size=128
      - (~98s/epoch)

4. KEY DISTINGUISHING FEATURES:
   - Reward type: "log_return"
     r = log(1 + port_ret_net) × 1000 - turnover_penalty - HHI_penalty
   - Variance penalty: 0.5 (HHI-based concentration penalty)
   - Policy: Flat Dirichlet (cash is a Dirichlet component)
   - This is the BASELINE experiment for LSTM architecture search


================================================================================
2) QQQ_LSTM_DAILY_2 — Hierarchical (HRA-SAC) with Log-Return Reward
================================================================================

1. GENERAL RL APPROACH:
   SAC with HIERARCHICAL Risk-Aware policy (HRA-SAC).
   Two-level action decomposition:
     Level 1: Cash timing head (Gaussian + sigmoid → equity_fraction ∈ [0.70, 0.98])
     Level 2: Stock selection head (Dirichlet-N over stocks only, no cash)
   Combined output: [equity_frac × stock_w, 1 - equity_frac]
   Cash timing is a separate 1D Gaussian learned from global features.

2. NUMBER OF CONFIGS: 2

3. CONFIGS:
   A) "hier_k20"
      - LSTM: hidden=64, layers=1, dropout=0.0
      - top_k=20
      - hierarchical=True, min_equity=0.70, max_equity=0.98
      - lr_actor=3e-4, batch_size=128

   B) "hier_k30"
      - LSTM: hidden=64, layers=1, dropout=0.0
      - top_k=30
      - hierarchical=True, min_equity=0.70, max_equity=0.98
      - lr_actor=3e-4, batch_size=128

4. KEY DISTINGUISHING FEATURES:
   - Reward type: "log_return" (same as DAILY_1)
   - Variance penalty: 0.5
   - Policy: HIERARCHICAL (cash timing separated from stock selection)
   - min_equity=0.70 → agent is always at least 70% invested in stocks
   - max_equity=0.98 → at most 98% invested
   - This tests whether separating cash timing from stock selection improves
     learning (gradient separation hypothesis)


================================================================================
3) QQQ_LSTM_NC_DAILY — No Cash, Benchmark-Relative Reward
================================================================================

1. GENERAL RL APPROACH:
   SAC with FLAT Dirichlet-(N+1) policy, BUT with force_fully_invested=True.
   The environment forces cash_weight=0 by renormalizing stock weights to
   sum to 1.0 after action. Agent still outputs N+1 weights but cash is
   zeroed out and redistributed.
   Reward directly optimizes for beating QQQ.

2. NUMBER OF CONFIGS: 3

3. CONFIGS:
   A) "bmk_nopen_k20"
      - LSTM: hidden=64, layers=1, dropout=0.0
      - top_k=20, variance_penalty=0.0
      - force_fully_invested=True
      - lr_actor=3e-4, batch_size=128

   B) "bmk_nopen_k10"
      - LSTM: hidden=64, layers=1, dropout=0.0
      - top_k=10 (more concentrated, closer to QQQ weighting)
      - variance_penalty=0.0
      - force_fully_invested=True
      - lr_actor=3e-4, batch_size=128

   C) "bmk_nopen_med_k20"
      - LSTM: hidden=128, layers=1, dropout=0.1
      - top_k=20, variance_penalty=0.0
      - force_fully_invested=True
      - lr_actor=3e-4, batch_size=128

4. KEY DISTINGUISHING FEATURES:
   - Reward type: "benchmark_relative"
     r = [log(1 + r_RL) - log(1 + r_QQQ)] × 1000 - turnover_penalty - HHI_penalty
     Directly optimizes for beating QQQ.
   - Variance penalty: 0.0 (agent CAN concentrate into mega-caps)
   - force_fully_invested=True → NO CASH DRAG (was costing ~1% ARC/year)
   - This addresses the structural gap to QQQ: cash drag + forced
     diversification were holding back performance

4) QQQ_LSTM_NC_DAILY_2 — No Cash v2, Mild Concentration Penalty
================================================================================

1. GENERAL RL APPROACH:
   Same as QQQ_LSTM_NC_DAILY (flat Dirichlet, force_fully_invested, benchmark-
   relative reward), but adds back a MILD concentration penalty (0.1) because
   v1 beat QQQ on ARC (19.7% vs 19.1%) but max drawdown was too high (41%
   vs 36%).

2. NUMBER OF CONFIGS: 3

3. CONFIGS:
   A) "bmk_mild_k20"
      - LSTM: hidden=64, layers=1, dropout=0.0
      - top_k=20, variance_penalty=0.1 (mild HHI penalty)
      - force_fully_invested=True
      - lr_actor=3e-4, batch_size=128

   B) "bmk_nopen_k20"
      - LSTM: hidden=64, layers=1, dropout=0.0
      - top_k=20, variance_penalty=0.0 (no penalty, same as NC_DAILY best)
      - force_fully_invested=True
      - lr_actor=3e-4, batch_size=128

   C) "bmk_mild_med_k20"
      - LSTM: hidden=128, layers=1, dropout=0.1
      - top_k=20, variance_penalty=0.1 (mild penalty)
      - force_fully_invested=True
      - lr_actor=3e-4, batch_size=128

4. KEY DISTINGUISHING FEATURES:
   - Reward type: "benchmark_relative" (same as NC_DAILY)
   - Variance penalty: 0.0 or 0.1 (mild, vs 0.5 in DAILY_1/2)
   - force_fully_invested=True (no cash)
   - Dropped k10 config from NC_DAILY (too concentrated → 41% MDD)
   - This is a refinement of NC_DAILY to improve risk-adjusted returns
     by limiting extreme concentration while still allowing mega-cap bets


================================================================================
5) QQQ_LSTM_LS_DAILY — Long-Short (130/30) Strategy
================================================================================

1. GENERAL RL APPROACH:
   SAC with FLAT Dirichlet policy. Key innovation: the ENVIRONMENT implements
   130/30 long-short portfolio construction WITHOUT any network changes.
   - Agent outputs standard Dirichlet-(N+1) positive weights
   - Environment: centers weights (w - mean), bottom stocks become negative
   - Scales: longs sum to 1.3, shorts sum to -0.3, net = 1.0
   - Agent learns via reward signal which stocks to underweight (= short)
   - Higher TC for shorts: tc_short_multiplier=5.0 (10bps vs 2bps for longs)

2. NUMBER OF CONFIGS: 3

3. CONFIGS:
   A) "bmk_all_long"
      - LSTM: hidden=64, layers=1, dropout=0.0
      - top_k=0 (FULL ~100 stock universe, no momentum filter)
      - Long-only, benchmark-relative reward
      - lr_actor=3e-4, batch_size=128

   B) "bmk_k20_long"
      - LSTM: hidden=64, layers=1, dropout=0.0
      - top_k=20 (momentum-filtered), long-only
      - lr_actor=3e-4, batch_size=128

   C) "bmk_all_130_30"
      - LSTM: hidden=64, layers=1, dropout=0.0
      - top_k=0 (full universe)
      - allow_short=True → 130/30 construction
      - cash_w=0 (fully invested by construction)
      - lr_actor=3e-4, batch_size=128

4. KEY DISTINGUISHING FEATURES:
   - Reward type: "benchmark_relative"
   - Variance penalty: 0.5
   - top_k=0 option → uses full ~100 NASDAQ-100 stock universe (no pre-filter)
   - allow_short=True → 130/30 long-short construction in environment
   - Short selling TC: 5x multiplier (10bps for shorts vs 2bps for longs)
   - This tests whether shorting underperformers and/or using the full
     universe improves returns vs the momentum-filtered top-k approach

6) QQQ_TRANSFORMERS_DAILY_1 — Transformer Temporal Encoder
================================================================================

1. GENERAL RL APPROACH:
   SAC with FLAT Dirichlet policy. The per-asset temporal encoder is replaced
   with a TRANSFORMER ENCODER (CLS token + learnable positional encoding +
   TransformerEncoderLayer with GELU activation). Drop-in replacement for the
   LSTM encoder. Cross-sectional attention and all other components unchanged.

2. NUMBER OF CONFIGS: 3

3. CONFIGS:
   A) "tf_2L_k20"
      - encoder_type="transformer" (Transformer encoder)
      - 2 layers, embed_dim=64, n_heads=4, dropout=0.1
      - top_k=20
      - lr_actor=1e-4 (LOWER than LSTM configs — Transformers need smaller LR)
      - batch_size=128

   B) "tf_2L_k30"
      - encoder_type="transformer"
      - 2 layers, embed_dim=64, n_heads=4, dropout=0.1
      - top_k=30
      - lr_actor=1e-4
      - batch_size=128

   C) "lstm_k20" (BASELINE for in-run comparison)
      - encoder_type="lstm" (standard LSTM)
      - 1 layer, hidden=64, dropout=0.0
      - top_k=20
      - lr_actor=3e-4
      - batch_size=128

4. KEY DISTINGUISHING FEATURES:
   - Reward type: "log_return" (same as DAILY_1/2)
   - Variance penalty: 0.5
   - Transformer encoder: CLS token, learnable positional encoding,
     TransformerEncoderLayer (GELU, 4x feedforward dim), 2 layers
   - Lower actor LR (1e-4 vs 3e-4) for Transformer stability
   - Includes LSTM baseline config for direct A/B comparison within same run
   - References: Zhang et al. 2020 (SARL), Xu et al. 2021, Ye et al. 2020

================================================================================
WHAT COULD POTENTIALLY BE CHANGED IN NEW CODE TO IMPROVE RESULTS
================================================================================

Based on the progression of experiments, the following observations stand out:

1. REWARD FUNCTION:
   - benchmark_relative (NC variants) showed promise by directly optimizing
     vs QQQ. Could try a hybrid: log_return + benchmark_relative weighting.
   - Risk-adjusted reward (e.g., differential Sharpe) was not the main reward
     in any final run — could be revisited with proper scaling.

2. VARIANCE/CONCENTRATION PENALTY:
   - 0.5 was too aggressive (over-diversifies, hurts returns)
   - 0.0 was too permissive (MDD too high in NC_DAILY)
   - 0.1 was the sweet spot in NC_DAILY_2 — continue exploring 0.05-0.15 range
   - Consider an ADAPTIVE penalty that increases during drawdowns.

3. CASH ALLOCATION:
   - force_fully_invested improved ARC by ~1% per year
   - Hierarchical cash timing (DAILY_2) is a more principled approach but
     adds complexity. Could revisit with better min/max equity bounds.

4. STOCK UNIVERSE:
   - top_k=20 was consistently best across runs
   - Full universe (top_k=0) was tested in LS_DAILY but adds dimensionality
   - Consider dynamic top_k selection or attention-based stock filtering.

5. ALPHA (ENTROPY TEMPERATURE):
   - Fixed alpha=0.2 was used across ALL runs due to divergence issues
   - The root cause: Dirichlet entropy is always positive (~+3 nats for K=21),
     target_entropy = -K*ent_mult is deeply negative → alpha diverges
   - Could try: (a) per-component target entropy, (b) different entropy
     formulation for simplex actions, or (c) entropy-constrained SAC.

6. ENCODER ARCHITECTURE:
   - Transformers (DAILY_1) tested but results vs LSTM unknown from code alone
   - Could try: (a) deeper Transformer (3-4 layers), (b) cross-asset
     Transformer (temporal + cross-sectional in one model), (c) CNN encoder.

7. TRAINING HYPERPARAMETERS:
   - 50 epochs with patience=8 may be too short — could try 80-100 epochs
   - Gradient steps=2 used throughout — could try 4 for more sample efficiency
   - Warmup=500 steps — could try longer warmup (1000+) for more exploration
   - Buffer=20,000 — relatively small, could try 50,000-100,000

8. WFO DESIGN:
   - All runs used 5yr train / 1yr val / 1yr test / 1yr step
   - Could try: shorter/longer train windows, overlapping test periods,
     or anchored (expanding) windows instead of sliding.

9. LONG-SHORT:
   - 130/30 construction in LS_DAILY is environment-level only
   - Agent doesn't explicitly learn to short — it learns positive Dirichlet
     weights that are post-processed into shorts via centering
   - A more principled approach: modify the network to output signed weights
     directly (e.g., Gaussian policy for individual stock weights).

10. MISSING EXPERIMENTS:
    - No run combines: Transformer + benchmark_relative + no cash
    - No run tests: different gamma values (currently all 0.99)
    - No run tests: different lookback windows (all use 60 days)
    - No run tests: different LR schedules (all use constant LR)
